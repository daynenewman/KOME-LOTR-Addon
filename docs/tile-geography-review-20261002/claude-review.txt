## Confirmed defects

**D1 — Moderate. The standing authority doc now contradicts shipped behavior.** `docs/KOME_TILE_WORLD_RESOLUTION.md` was not updated; grep finds no mention of exclusion metadata in any standing doc. Specifically `:367-368` ("`capturable()` is empty because no authoritative area-capturability metadata exists") is now false per `KOMETileResolution.java:53-55`; the status table `:358-365` omits `CLASSIFIED_EXCLUSION`; `:361` defines `IN_BOUNDS_GAP` as covering *all* alpha≤24/retired cells; `:474-477` still lists "uncapturable-area metadata" as deferred; `:386-393,410-419` omit the now-mandatory TSV and the mask pin that can fail `reloadBundled()`. `docs/KOME_SERVER_TILE_AWARENESS.md` — the doc `KOMEServerTileAwareness.java:23` points to — omits the zone-metadata comparison and the `STALE_GEOMETRY`/`GEOMETRY_CHANGED` metadata-replacement path.

**D2 — Low/Moderate. Per-record regex recompilation on the startup load path.** `String.matches` compiles a fresh `Pattern` per call. `KOMETileExclusions.java:130` compiles one per coordinate and `:109` calls it three times per `run`; a fully populated 4 MiB file (~280 k runs) is ~840 k `Pattern.compile` calls — order of seconds added to `KOMEAddon.postInit`. `:101` adds two more per `zone`. Zero impact today (empty set), but it lands exactly when KOM-58 classifications are approved. Fix: `static final Pattern` constants.

**D3 — Moderate. Performance evidence never covers a populated exclusion index.** `measurements.txt:47` shows `exclusionIndexBytes=0` — both random-access lookup figures and the heap figure were taken while `cells == null`, where `KOMETileExclusions.at()` short-circuits and touches no array. The synthetic full-size index (`measurements.txt:50-51`, `KOMETileGeographyMeasurement.java:58-65`) is exercised at **one fixed coordinate** in a tight loop, then replaced — a cache-resident best case, not comparable to the random workload at `:41-46`. There is also no measured heap with the synthetic snapshot resident and no parse time for a nonempty metadata file. So README line 48 ("No additional caching/index optimization justified by these measurements") is unsupported for the populated configuration.

**D4 — Low/Moderate. The production load path's failure mode is untested.** `reloadBundled()` is the only production entry point and the TSV is mandatory there, but no test exercises it failing on bad/missing *bundled* metadata — `KOMETileExclusionsTest.java:131-143` uses the package-private `reload(...)` overload, and `KOMETileWorldResolverTest.java:213` covers only LOTR-dimension disagreement. The classloader-substitution pattern at `KOMETileGameplayDefaultsTest.java:105-115` is directly reusable.

**D5 — Low/Moderate. KOM-59 provenance isn't re-verifiable here.** `historical-provenance.json` names `v2-geography-review-20260920/cell-review.csv` (212,449,646 B) and three others; none exist in this worktree (those folders contain only `edit-manifest.csv`), and no absolute root or owning worktree HEAD is recorded. The atlas *is* reproducible from the hash-pinned `review-inputs.csv`; the derivation *of* that file is not checkable.

**D6 — Low. Stale/unindexed evidence.** `focused-results.json:24-29` reports `KOMETileExclusionsTest: 8` vs `build-results.json:731-736`'s 10 (two added at checkpoint 1 per `PROGRESS.md:12`), with no run label — the two artifacts read as contradictory. `focused-results.json`, `atlas-summary.json` and `preservation-after.json` are unreferenced from the README, including the file carrying the actual preservation verification.

**D7 — Low. Build evidence is transcribed, not reproducible.** `PROGRESS.md:20` discloses the Gradle transcripts were edited post-run, so `clean-build.txt` is not byte-faithful; `build-results.json`/`measurement-summary.json` have no committed generator and the JUnit XML isn't committed.

**D8 — Low. Unguarded `Optional.get()` in the client tick handler.** `KOMECurrentTileHud.java:133` calls `location.exclusion().get()` twice. The invariant holds today, but `KOMETileResolution.java:25-30` defaults `exclusion` to null, so a future producer that forgets would throw `NoSuchElementException` on the client tick.

**D9 — Low (hardening). The newly hash-pinned mask has no `.gitattributes` entry.** `.gitattributes:3` pins the checksummed `kome_tile_*` datasets, but nothing covers `src/main/resources/assets/kome/map/**` even though the TSV hard-pins the PNG's SHA-256. Git's binary heuristic makes real corruption unlikely — so this is residual risk, not a live break — but the consequence of a mismatch is a whole-feature `INVALID_SNAPSHOT`.

**D10 — Low. Geometry+metadata soft-fails while its sibling dataset hard-fails.** `KOMEAddon.java:113` throws for the gameplay dataset; `:114-116` only prints to stderr when `reloadBundled()` fails. Pre-existing, but KOM-58 widens the trigger surface. A build-time guard exists (`KOMETileTestResources.java:15` makes ~100 tests fail on drift), so this is about runtime diagnosability.
