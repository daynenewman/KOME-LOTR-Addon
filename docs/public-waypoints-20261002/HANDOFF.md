## Final behavior

- Additive `PublicWaypoints` section in canonical `KOME_ServerRules`, registry schema 1; root schema remains 5. Stable UUIDs and never-reused negative wire IDs, exact configured-dimension/XZ tile resolution, zero-or-one approval per tile. Invalid/orphaned/conflicting persisted rows are quarantined deterministically; all valid duplicate contenders are withheld. Geometry-unavailable or write-blocked destinations cannot travel. Existing atomic world-load guard remains intact.
- Default/current owners are derived from canonical tile state. Capture does not overwrite the independent persisted nonnegative level; level has no new gameplay meaning. Presentation contains approved records/owners/cutover aliases only, without pending proposals or private audit/approval identities.
- Bounded complete snapshots publish on login and periodic server checks, independent of fellowships. Actual Forge encoding and NetworkManager write receipts distinguish failed writes from send-call completion. Partial/old/conflicting publications cannot replace the immutable client state; connection and sequence fences clear stale state at disconnect/reconnect/server switches. Successful writes are not client application acknowledgements.
- Transient LOTRCustomWaypoint-compatible adapters compose native map lists without adding records to native saved waypoint lists. Native points remain available unless explicitly associated; exact converted legacy identities are suppressed until explicit rollback. Public selection follows rename/move/removal; private rename/delete/share/hide controls are suppressed for public markers. Native completion-screen/use-count lookup recognizes only the reserved public namespace on clients.
- Public requests and native completion execute through the server tick queue, fenced to the current connection. Current approval, native configuration/dimension/cooldown/combat/sleep/progression, canonical ownership, active war and faction relations are checked. Final travel revalidates removal/move/current policy; no operator policy bypass or level gate. Existing native chunk/teleport/companion/cooldown/use-count behavior is retained rather than reimplemented.
- `/kome waypoint propose <name>` captures the normal server player's position; pending is neither public nor travelable. Permission-level-2 commands inspect, adjust, approve or reject with an expected proposal version, retain history, and revalidate exact tile/uniqueness before publication. Administrative add/associate/rename/move/remove/level commands use the same registry.
- Migration inventory is explicit and read only: active fellowship UUID plus **administrator-confirmed dimension**, because native custom records do not persist dimension. Dry run reports exact owner/custom-ID identity, name/position, tile, all ambiguity and invalidity. Conversion requires a fresh matching token and explicit selection, validates the entire batch, preserves originals, and publishes exact cutover aliases. Removal keeps aliases; rollback removes the exact alias/public record so original visibility can return.

Common record/registry, proposal and migration code is in `src/main/java/kome/common/data/`; command authority is `KOMEWaypointCommands`. Network synchronization is `KOMEPacketPublicWaypoints` / `KOMEPublicWaypointSync`; native boundaries are `KOMEPublicWaypointBridge`, `KOMEPublicWaypointAdapter`, `KOMEPublicWaypointTransformer` and client `KOMEPublicWaypointMapHooks`.
