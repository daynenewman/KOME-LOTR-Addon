# Tiles, ownership, map geometry, and location

[Index](../../INDEX.md)

Owns world/map coordinate resolution, bundled tile geometry, gameplay defaults, tile control, and map/HUD presentation. Raster contact, rendered borders, strategic graph edges, and authorized passage are independent.

[KOM-59 T351/T352 correction](../../../kom59-ithilien-route-20261010/README.md) opens the existing direct default edge and removes its false river marker. The historical decorative-color water inference was wrong for this pair. Raster/IDs/reference coordinates remain unchanged; saved overrides still win. This narrow approval does not resolve the atlas's uncertain cells or establish actual server terrain/permissions.

[Approved KOM-59 mountain separation](../../../kom59-mountain-separation-20261010/README.md) removes exactly 45 canonical cells across five mountain contacts and classifies them using 25 hash-bound runs. Active IDs and gameplay graph/defaults stay unchanged; adoption into existing worlds requires an authoritative stopped-save and physical-entity inventory. Other geography proposals remain outside this approval.

## KOM-85 Phase 1 territory presentation

[KOMETerritoryStyle](../../../../src/main/java/kome/client/KOMETerritoryStyle.java) owns active client palette/display choices. Defaults remain Classic LOTR, Full territory color, 50% territory opacity and individual tile borders off. Current KOME retains the previous native LOTRFaction RGB/hash fallback. Visual controls are on the left and layer toggles on the right. Since Phase 1E, [KOMEClientConfig](../../../../src/main/java/kome/client/KOMEClientConfig.java) stores these installation-local preferences between restarts; see native artwork, configuration keys and verification below. There are no server rules, world-save fields or packets for these preferences.

Only `KOMEClientData.conquestRenderOwners()` from a completed public snapshot supplies ownership. `KOMEConquestMapOverlay.prepareTerritoryColors` caches derived owner/color maps by conquest revision and palette; changing display mode reuses them. Fill uploads remain lazy and compare exact colors plus opacity alpha; opacity changes do not rebuild the owner/color maps or raster geometry. Geometry clear/reload/disconnect also clears the derived maps and rendered opacity. Palette switches do not rebuild raster geometry.

`KOMEMapBorders.drawTerritories` derives boundaries from the existing cached raster edge/fill runs. It suppresses same-owner edges and retains different-owner boundaries even when their palette RGB is identical. The six-GUI-pixel inward treatment remains four 1.5-pixel bands at alpha 255/176/96/36, clipped exactly to owned land and gaps. No black casing is added. Dark factions retain the half-pixel pale rim, now precomposited into the opaque outer faction band exactly once.

The forensic-review correction uses [KOMETerritoryMesh](../../../../src/main/java/kome/client/KOMETerritoryMesh.java) to sweep the clipped axis-aligned rectangles into a disjoint partition. At each point it chooses the strongest band (or the precomposited rim) instead of blending overlapping strips. Compatible horizontal spans and vertical rows coalesce. This avoids extra alpha at corners, bends and adjoining segments without removing boundary coverage or approximating the owned polygon with a pixel raster.

Phase 1C replaces the single exact-zoom mesh with [KOMETerritoryFrameCache](../../../../src/main/java/kome/client/KOMETerritoryFrameCache.java): at most three stable meshes, each padded by 64 GUI pixels, sharing one 25,000,000-byte reservation. The reservation includes primitive rectangles, future lazy direct vertices and a conservative allowance for copied owner/color maps and frame objects. Direct-buffer compilation remains limited to 250,000 quads per mesh; complete larger meshes can be retained in streaming form when they fit the aggregate budget. Exact owner/color comparisons catch in-place changes. Palette, mode, opacity and tile-edge preference changes clear territory meshes; immutable raster geometry remains reusable. Geometry replacement, resolver loss, reload and disconnect clear all retained frames. Transient union construction and buffers awaiting GC are outside the retained-reference budget.

`KOMEConquestMapOverlay.drawTerritoryMesh` submits retained C4UB/V3F client-array data through one OpenGL 1.1 draw call; Java no longer replays every faction quad through Tessellator each frame. It restores matrix, client arrays, prior VBO binding, current color and scissor state, and intersects any incoming scissor. No shader, framebuffer, display-list resource or rendering framework is introduced. Raster reload/disconnect drops the mesh with its owning geometry; direct buffers become GC-eligible and there are no new GL object names to delete. Hover, optional individual tile edges and destination cues keep their existing paths. Borders-only still skips ownership fill, desert shade and hover fill.

The independent GL review found that LWJGL 2.9.4 validates sixteen remaining integers for `glGetInteger(IntBuffer)`, including four-value scissor queries. The shared direct/native-order scissor scratch now has capacity 16; both queries still call `clear()` and read indices 0-3. The adjacent VBO-binding query uses the scalar overload. A context-free regression reproduced the production four-element buffer failure, then passed with the corrected allocation; a bytecode regression checks that both queries reset the shared buffer and remain guarded by incoming scissor enablement. Existing state cleanup remains covered structurally, without claiming GL-driver execution. Saved evidence is under `build/kom85-scissor-{red,green,focused}*`: directly affected lifecycle tests passed 9/9, and the eight-suite selection passed 151 tests (149 previous non-benchmark cases plus two new regressions), zero failures/errors/skips. The previous expensive real-raster benchmark was excluded for this allocation-only correction; its metrics and the earlier 150-test evidence remain preserved. Java compilation and `git diff --check` passed. Live GL/visual acceptance remains pending.

Classic LOTR now reads native `LOTRFaction.getFactionColor()` values rather than approximating bundled faction colors. A one-time client lookup indexes native enum/code names and native aliases, plus canonical KOME keys through the existing read-only `KOMEAlliance.normalizeFactionKey` rules. No localized faction-name calls or server ownership changes are involved. All native factions, including non-playable Utumno, are indexed. ## KOM-85 Phase 1C native zoom reuse (fallback limitation remains)

The overlay consumes native interpolated position and zoomScale, including the partial tick already applied by LOTR (sampled at the common terrain exit since the Phase 1D waypoint follow-up below). It reads zoomTicks and zoomScaleStable to plan the six-tick transition; it does not call native interpolation again. [KOMEMapViewport](../../../../src/main/java/kome/client/KOMEMapViewport.java) supplies one shared affine scale/translation for the GL matrix and context-free rectangle adapter. Scaling a disjoint mesh preserves faction RGB and single-contribution alpha. Its apparent border width may change during animation; settled requests require the exact final scale and restore the configured six-pixel treatment. Hover, tile-edge and destination geometry remain on their existing current-viewport paths.

Before reuse, a frame must cover the entire map-coordinate viewport at the smaller native endpoint scale, at the current center. This conservative envelope also covers each intermediate scale. If no retained frame covers it, construction occurs once at that stable smaller scale, never at each interpolated scale. A locked animated frame avoids switching between available meshes during a transition. Every request rechecks coverage and content, so panning, reversal, interruption and ownership changes cannot stretch incomplete or stale coverage. Settled lookup additionally requires exact zoom. Covered pan/resize requests reuse meshes; leaving coverage still requires construction.

[KOMETerritoryZoomTest](../../../../src/test/java/kome/client/KOMETerritoryZoomTest.java) calls the actual jar's setupZoomVariables method for six ticks with partial frames 0, 0.25, 0.5 and 0.75. Original code passed the forcibly rerun 152-test baseline; both initial new zoom regressions failed RED with 25 distinct meshes. The corrected focused selection passes 163 tests, zero failures/errors/skips. Coverage includes outward exposure of a previously unseen gap boundary, affine position agreement, direction reversal/interruption, pan reuse, exact settled width, alpha compositing, ownership/settings invalidation, LRU eviction, lazy-buffer reservations and actual reload/disconnect callbacks. A bytecode regression checks native-field dispatch, scoped affine submission and presentation invalidation. Existing controls, palette mappings, compositing and scissor regressions remain included.
